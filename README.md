## Roomly 是什么

不是让室友共享更多，而是让责任、边界、公平和规则变得更清楚。

> 合租不是成为一家人，而是让一群不同的人，可以舒服地住在一起。

面向北京、上海、深圳通过租房中介（自如等机构）随机合租的年轻租客：入住前彼此不认识，成员不断搬入搬出，工作忙、时间少，更希望"互不打扰"而不是强行建立亲密关系，很多事情不好意思直接开口。

Demo House：**望京西园三区 · 503**（租房中介托管房源）

## 八条设计原则

产品里每一处判断都回到这八条：

1. **公平不等于平均** —— 系统发现可能影响公平的情况，但最终由用户决定怎么处理
2. **边界优先于共享** —— 物品分公共 / 可借 / 私人，空间分区到人
3. **系统承担中立提醒** —— 把人际矛盾转化为"规则与当前状态的偏差"
4. **House 长期存在，成员不断变化** —— 有人搬走，这个家不会被删除
5. **低频建立规则，高频自动执行** —— 用户只在建规则、出异常、需确认时介入
6. **AI 只理解和建议，不替人做关键决定** —— 先展示理解结果和影响，再让用户确认
7. **不公开羞辱任何成员** —— 没有举报、违规榜、排名、处罚
8. **普通摩擦与安全事件分开** —— 涉及人身安全时不再引导"好好沟通"

## 信息架构

| 一级 | 回答的问题 | 包含 |
|---|---|---|
| **首页** | 这个家今天怎么样？我要处理什么？ | House 状态、今天值得留意、今天需要你处理、跟管家说一句、House 动态 |
| **生活** | 这个家此刻怎么运转？ | 值日、公共物品、公共空间、访客、离家、共享设施 |
| **账单** | 为什么这样算？ | 公共费用、多种分摊、情境公平提示、月末净额结算 |
| **共识** | 我们约定了什么？ | 当前规则、正在讨论、入住共识、新室友差异、居住问题记录、有件事不好开口 |
| **我的** | 我在这个家里是什么状态？ | 状态、偏好、空间、物品、责任、账单、房屋服务、搬出 |

「跟管家说一句」是**全局能力**，不是单独的 AI 聊天 Tab。

## 四条典型情境

第一次打开的人不用自己摸索：右下角「演示控制台」里有四条预置情境，每条都带一步步的任务提示，可以直接切换需要的室友身份。四条情境各有一份独立数据，互不影响，随时重置或退出回到自由探索。

| | 情境 | 走完会看到 |
|---|---|---|
| **A** | 新室友加入 | 偏好比较 → 识别差异 → 共同讨论 → 修改方案 → 全员确认 → 规则更新 |
| **B** | 访客临时例外 | 触及上限 → 发起例外申请 → 室友分别回应 → 例外生效 → 到期恢复 |
| **C** | 离家与账单公平 | 登记离家 → 值日受影响 → 分摊方案 → 成员确认 → 更新账单 → 月末结算 |
| **D** | 室友搬出 | 搬出准备 → 机构确认（模拟）→ 任务与分区交接 → 历史账务结清 → 成员关系结束 |

控制台里还能推进演示时间（一天 / 下一周 / 月末）：临时例外会到期失效、访客留宿次数跨周归零、离家计划自动结束、值日生成下一期。已经发生的记录不会因为时间推进被删掉。

## 四条核心演示链路

**1 · 新室友加入，只协商真正变化的部分**
共识 → Lin 将在 9月20日入住 → 系统把她填的偏好和 House 现状逐项比对：6 项一致（收起、按需展开）、2 项差异（访客留宿、空调温度）直接进入「正在讨论」→ 每个人对当前方案表态（同意 / 不同意 / 再想想），随时可改，议题不会因为谁点了一下就消失 → 需要的人都接受了才写进「我们已经说好的」。**讨论期间原约定一个字都不改**；方案被修改就是新版本，旧表态自动失效、要重新确认。谈不拢也有明确结果：改一版折中方案、限时试行两周、或者这次就不调整。**共识是过程，规则只是结果，不是投票。**

**2 · 自然表达 → 结构化理解 → 可以改 → 影响 → 确认 → 跨模块生效**
首页管家输入「我刚买了29块9的厕纸，12卷，三个人平分」→ 管家把它拆成物品、数量、金额、垫付人、参与人，**每一项都能当场改**（说「这次 Tom 不用分」，Tom 就真的被去掉）→ 展示确认后会发生什么 → 确认：库存 2→14 卷、首页提醒消失、账单新增一笔、净额重算、House 动态增加记录。缺信息只问缺的那几项，绝不自己填一个会把账算错的数字；听不懂就说明原因并给出能直接去做这件事的入口；一句话里有两件事，先问你要做哪一件。**最后执行的，就是预览里看到的那一份。**

**3 · 情绪 → 问题 → 诉求 → 可执行规则**
「有件事不好开口」→ 选类型（访客）→ 自然表达「Alex 女朋友最近基本天天来」→ 管家识别出这件事可能涉及留宿频率 / 公共空间占用 / 实际居住人数 / 水电公平 → 你最希望解决什么 → 查现有规则 → 决定怎么处理。发起匿名讨论前，会先把**其他人实际会看到的那段文字**摆给你看，指出哪几处可能暴露你的身份，可以一键换成不指向具体某个人的说法。产品不承诺绝对匿名——能做到的是系统不显示发起人、不写进家里动态，剩下的由你决定写多少。

**4 · 离家 → 家务调整 → 情境公平**
Tom 9月9日—9月18日离家 10 天 → 值日暂缓并后续补偿 → 账单页出现公平提示 → ¥360 水电按登记在住天数：Yiming ¥135 / Alex ¥135 / Tom ¥90 → 但一个人只能**提出**方案，要相关成员各自确认才会生成账单。系统不会因为谁点了一下，就说「已由全员确认」。

**5 · 长期规则下的临时例外**
约定是「同一访客每周最多留宿 2 晚」。住满 2 晚之后还想再住一晚，不用为这一次去改长期约定——可以只申请一次例外：说清楚哪位访客、几晚、到什么时候 → 在住室友**分别**回应（发起人不能替别人同意）→ 全部同意才生效，这几晚正式登记、**只记一次**，也不再被判成超出约定 → 本周结束自动失效，长期约定一个字没动。如果这种情况以后会经常发生，可以从例外直接转进共识讨论。

## 其他能力

- **多人审批** —— 借物、换班、分区调整、留宿例外、分摊方案共用一套生命周期：发起申请 → 等待回应 → 申请通过 → 执行完成。需要谁回应写得清清楚楚，**发起人不在这个名单里**；有一个人不同意就不会显示成通过，可以撤回或转成讨论；到期自动失效，不会永远挂着。每个人都能看到自己要不要回应、别人进行到哪一步
- **按份结清** —— 一笔账拆成每个人那一份：本人标记已付 → 垫付人确认收到，两步都完成这一份才算清，一个人点一下只代表他自己那一份。金额全程按「分」计算，各人相加永远等于总额；已经确认收款的份额不能被悄悄改掉，要先撤销结清。某位成员的账是否了结，只看和他自己有关的那几份——别人之间还没结的账不会把他卡住
- **操作都有真实结果** —— 私下沟通、中立提醒、管家回执、洗衣机提醒都会落成**模拟站内消息**，切换体验身份就能看到对方收到了什么；机构侧的受理、退租确认都明确标注是演示行为。产品不会在什么都没做成的时候提示「已发送」
- **成员生命周期** —— pending（租约已签未入住）→ active → moved_out_pending_settlement（已搬出待结清）→ ended；权限按状态给：即将入住的只看与自己有关的讨论、约定和分区，已搬出的只剩历史账单可付可收
- **公共空间分区** —— 冰箱、厨房储物柜、卫生间置物架、鞋柜分区到人；个人不能直接改公共分区，只能「申请调整」，对方同意后互换
- **访客规则检查** —— 访客有轻量身份（称呼，不需要真名），「同一访客每周最多留宿 2 晚」按人分开累计；超出的那几晚不会先记上再补审批，而是走临时例外，批准之后才登记。页面上能分清正常登记、待批准申请、已批准例外和被取消的申请
- **值日换班** —— 「今天做不了」提供不在家 / 太忙 / 想换班，换班会推荐当前无冲突的人；责任分布只解释不排名
- **净额结算** —— 自动抵消相互欠款，¥10 以下滚入下月
- **逐级处理** —— 中立提醒 → 私下提醒 → 重新明确规则 → House 讨论 → 请管家协调；记录的是"最近 14 天出现 2 次提醒"而不是"谁违规 2 次"
- **安全事件独立路径** —— 保存记录、联系平台、紧急联系人、报警指引
- **临时离家 ≠ 正式搬出** —— 「登记离家计划」影响值日暂缓和水电按天数分摊；「搬出与退租」是清单式准备，完成清单还要等租赁机构确认退租，账全部结清成员关系才结束，House 继续存在
- **我的偏好 ≠ 共同约定** —— 个人偏好只属于本人，接受共同方案不会改写它；偏好与约定不同时只提示去讨论
- **红点只表示"需要我做的事"** —— 生活 = 轮到我的值日 + 等我回应的请求，账单 = 等我付的份额，共识 = 等我表态的议题；"家里还有事没结束"不等于"我要做事"

## 技术说明

限时 4 小时的产品雏形，聚焦产品思路与交互完整性；代码由 AI coding 工具生成。

- 零构建依赖的静态站点，秒级部署、无冷启动
- 原生 JS 状态驱动渲染，所有模块共享同一份 state，保证跨模块联动与 House 一致性
- 演示状态只存在当前标签页的 `sessionStorage` 里：同一标签页刷新会保留操作，新开页面 / 换个人打开都是同一份固定的初始数据；左下角也可以随时重置
- 时间是模拟的：所有需要判断「到期没有、是不是本周」的记录都带一个相对基准日的天数，显示文字现算，演示控制台推进时间时整套状态跟着重算
- 响应式：桌面端左侧导航，移动端底部标签栏
- 深浅色主题自适应

```
index.html      外壳与全部样式（设计 token、组件层、响应式）
js/data.js      House、成员、偏好模型、种子数据、派生计算（按份结清、净额结算、留宿与例外、请求审批）
js/views.js     五个一级页面及各自子页面
js/flows.js     管家理解、入住共识问卷、不好开口、临时例外、安全处理、各类登记
js/demo.js      模拟时间推进与四条典型情境
js/app.js       渲染循环与动作分发
```

本阶段有意省略：登录注册、后端与数据库、真实支付、消息推送、多 House 管理、真实 AI 模型接入（管家的理解为规则解析实现）。
